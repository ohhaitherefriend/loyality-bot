# 👨‍💼 Система администраторов

## 🔐 Как работает разделение ролей?

В боте используется **одно приложение для всех**, но с разными интерфейсами в зависимости от роли пользователя.

### Роли пользователей

```java
public enum UserRole {
    USER,   // Обычный клиент - 🛍 покупки, 💰 баллы
    ADMIN   // Администратор - 🔑 активация кодов, 📢 рассылки
}
```

### Как определяется роль?

1. **При регистрации** (`/start`) - автоматически `USER`
2. **В базе данных** - поле `role` в таблице `users`
3. **При каждом действии** - проверка `user.getRole() == UserRole.ADMIN`

## 🚀 Способы создания администратора

### Способ 1: Через SQL (текущий)

1. Зарегистрируйтесь в боте как обычный пользователь
2. Откройте H2 Console: http://localhost:8080/h2-console
3. Выполните SQL:
```sql
UPDATE USERS SET ROLE = 'ADMIN' WHERE PHONE_NUMBER = '+79001234567';
```
4. Перезапустите бота (`/start`) - увидите админское меню!

### Способ 2: Через секретный код (рекомендуется - см. ниже)

Добавьте в `.env`:
```
ADMIN_SECRET_CODE=your_secret_code_here
```

Затем в боте отправьте команду:
```
/makeadmin your_secret_code_here
```

Если код верный - вы станете администратором!

### Способ 3: Через другого администратора

Если у вас уже есть администратор, он может назначать других:
```
/promote @username
```
или
```
/promote +79001234567
```

## 🔒 Безопасность

### Защита админских функций

Каждая админская функция проверяет роль:

```java
private void handleEnterCodeButton(Long chatId, User user) {
    if (user.getRole() != User.UserRole.ADMIN) {
        sendMessage(chatId, "❌ Эта функция доступна только администраторам");
        return;
    }
    // Админский код выполняется только для ADMIN
}
```

### Рекомендации:

1. ✅ **Секретный код** храните в `.env` файле (не в коде!)
2. ✅ **Не делитесь** секретным кодом
3. ✅ **Меняйте код** после создания первого админа
4. ✅ **Логируйте** все админские действия
5. ✅ **Ограничьте** количество администраторов

## 📊 Проверка текущих администраторов

### SQL запрос:
```sql
SELECT chat_id, phone_number, first_name, last_name, role, created_at
FROM users
WHERE role = 'ADMIN'
ORDER BY created_at;
```

### Через бота (для админов):
```
/admins - список всех администраторов
```

## 🎯 Иерархия ролей (для будущего развития)

Можно расширить систему ролей:

```java
public enum UserRole {
    USER,           // Обычный клиент
    CASHIER,        // Кассир (только активация кодов)
    MANAGER,        // Менеджер (кассир + рассылки)
    ADMIN,          // Администратор (всё + назначение ролей)
    SUPER_ADMIN     // Супер-админ (всё + настройки системы)
}
```

## 💡 Примеры использования

### Сценарий 1: Первый запуск системы

1. Владелец магазина регистрируется в боте
2. Запускает приложение и видит в логах свой `chat_id`
3. Выполняет SQL запрос для назначения себя админом
4. Перезапускает бота - видит админское меню
5. Создает коды для кассиров

### Сценарий 2: Назначение кассира администратором

1. Кассир регистрируется в боте
2. Администратор видит его номер телефона
3. Выполняет в H2 Console:
```sql
UPDATE users SET role = 'ADMIN' WHERE phone_number = '+79991234567';
```
4. Кассир перезапускает бота - получает админские права

### Сценарий 3: Несколько магазинов (future)

Можно добавить поле `store_id` к пользователям:
```sql
ALTER TABLE users ADD COLUMN store_id BIGINT;
```

И админы будут видеть только своих клиентов.

## 🔍 Мониторинг действий администраторов

Все админские действия логируются:

```java
log.info("Admin {} activated code {} for user {}", 
    admin.getChatId(), code, customer.getChatId());
```

Смотрите логи:
```bash
tail -f logs/spring.log | grep "Admin"
```
