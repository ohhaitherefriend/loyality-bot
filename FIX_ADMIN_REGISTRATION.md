# Исправление: Администраторы должны быть полностью зарегистрированы

## Проблема на скриншоте

```
Пользователь: DnemSOgnem
1. Стал администратором
2. Нажал /start → получил админское меню
3. Нажал "🔑 Ввести код покупки"
4. Ввел "8300088" (код покупки от клиента)
5. БОТ ПРИНЯЛ ЭТО КАК НОМЕР ТЕЛЕФОНА! ❌
6. "✅ Регистрация успешна! Телефон: 8300088"
```

## Почему это произошло

Администратор был назначен **БЕЗ прохождения регистрации**:
- У него не было номера телефона (`phone_number` = пустой или NULL)
- Его состояние было `AWAITING_PHONE` или `NEW`
- При нажатии любой кнопки бот проверял: "нет телефона → попросить ввести"
- Код покупки "8300088" (7 цифр) был принят как "телефон"

### Старая логика была уязвима

```java
// Бот проверял состояние ПЕРЕД обработкой админских кнопок
if (user.getState() == User.UserState.AWAITING_PHONE) {
    handlePhoneNumber(chatId, update, user);
    return; // ← Администратор попадал сюда!
}

// До этой проверки дело не доходило:
if (messageText.equals(BTN_ENTER_CODE)) {
    handleEnterCodeButton(chatId, user);
}
```

## Что было исправлено

### 1. Проверка при назначении администратора

**В `handleMakeAdminCommand()`** добавлена проверка:

```java
// Проверяем, что пользователь прошел полную регистрацию
if (user.getState() != User.UserState.REGISTERED || 
    user.getPhoneNumber() == null || 
    user.getPhoneNumber().trim().isEmpty()) {
    sendMessage(chatId, 
        "⚠️ Для получения прав администратора необходимо сначала завершить регистрацию!\n\n" +
        "Пожалуйста, отправьте /start и зарегистрируйте свой номер телефона.");
    return;
}
```

Теперь `/makeadmin` работает **только** если пользователь:
- ✅ Имеет валидный номер телефона
- ✅ Находится в состоянии `REGISTERED`

### 2. Проверка во всех админских функциях

Добавлена проверка в **каждую** админскую кнопку:

```java
private void handleEnterCodeButton(Long chatId, User user) {
    if (user.getRole() != User.UserRole.ADMIN) {
        sendMessage(chatId, "❌ Эта функция доступна только администраторам");
        return;
    }
    
    // НОВАЯ ПРОВЕРКА:
    if (user.getState() != User.UserState.REGISTERED) {
        sendMessage(chatId, 
            "⚠️ Пожалуйста, завершите регистрацию перед использованием административных функций.\n\n" +
            "Отправьте /start и зарегистрируйте свой номер телефона.");
        return;
    }
    
    // Теперь безопасно использовать админские функции
    userService.updateUserState(user, User.UserState.AWAITING_ADMIN_CODE);
    sendMessage(chatId, "🔑 Введите код покупки от клиента:");
}
```

Такая же проверка добавлена в:
- ✅ `handleEnterCodeButton()` - ввод кода покупки
- ✅ `handleSendDiscountButton()` - создание промо-акции
- ✅ `handlePromotionsButton()` - просмотр акций
- ✅ `handleStatsButton()` - статистика

### 3. Обновлен SQL скрипт

Обновлен `scripts/create-admin.sql` с:
- ⚠️ Предупреждениями о необходимости валидного телефона
- ✅ Примерами правильного создания админа
- ❌ Примерами что НЕ надо делать
- 🔧 Скриптом для исправления существующих админов

## Теперь невозможно

❌ Создать админа без номера телефона через `/makeadmin`  
❌ Использовать админские функции без завершения регистрации  
❌ Ввести код покупки вместо телефона при регистрации (валидация)  
❌ Иметь дубликаты номеров телефонов (unique constraint)  

## Что нужно сделать

### Для исправления существующих администраторов

#### 1. Найдите проблемных админов

```sql
SELECT 
    id, chat_id, phone_number, first_name, role, state
FROM users 
WHERE role = 'ADMIN' 
AND (
    phone_number IS NULL 
    OR phone_number = '' 
    OR LENGTH(REGEXP_REPLACE(phone_number, '[^0-9]', '')) < 10
    OR state != 'REGISTERED'
);
```

#### 2. Исправьте их

**Вариант A: Обновите номер телефона на настоящий**

```sql
UPDATE users 
SET 
    phone_number = '+79001234567',  -- Реальный номер админа!
    state = 'REGISTERED'
WHERE role = 'ADMIN' 
AND chat_id = 123456789;  -- chat_id админа
```

**Вариант B: Снимите права админа и попросите перерегистрироваться**

```sql
UPDATE users 
SET 
    role = 'USER',
    phone_number = '',
    state = 'NEW'
WHERE role = 'ADMIN' 
AND chat_id = 123456789;
```

Затем админ должен:
1. Отправить `/start`
2. Правильно зарегистрироваться с номером телефона
3. Использовать `/makeadmin СЕКРЕТ`

### Для новых администраторов

**Правильный порядок действий:**

1. ✅ Пользователь пишет `/start` боту
2. ✅ Бот просит номер телефона
3. ✅ Пользователь вводит **НАСТОЯЩИЙ** номер телефона
4. ✅ Регистрация успешна (`state = REGISTERED`)
5. ✅ Пользователь вводит `/makeadmin СЕКРЕТНЫЙ_КОД`
6. ✅ Получает права администратора
7. ✅ Может использовать все админские функции

## Проверка после исправления

```sql
-- Все админы должны иметь валидные номера
SELECT 
    id, chat_id, phone_number,
    LENGTH(REGEXP_REPLACE(phone_number, '[^0-9]', '')) as digits,
    state, role
FROM users 
WHERE role = 'ADMIN';
```

Убедитесь:
- `digits` >= 10 (минимум 10 цифр)
- `state` = 'REGISTERED'
- `phone_number` не пустой и не похож на код (не 6-8 цифр)

## Связанные исправления

Эти изменения работают вместе с:
1. ✅ Валидация формата телефона (минимум 10 цифр)
2. ✅ Unique constraint на `phone_number`
3. ✅ Скрипты очистки невалидных пользователей
4. ✅ Скрипты исправления дубликатов

## Резюме

**Проблема:** Админы без телефона могли случайно зарегистрироваться с кодом покупки  
**Решение:** Админы обязаны быть полностью зарегистрированы перед использованием функций  
**Результат:** Невозможно использовать админские функции без валидного номера телефона  

🎉 Теперь система полностью защищена от этой ошибки!
