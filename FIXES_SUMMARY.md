# Резюме всех исправлений

## 🔴 Исходная проблема

```
org.springframework.dao.IncorrectResultSizeDataAccessException: query did not return a unique result: 9
```

**Причина:** 9 пользователей имели одинаковый "номер телефона" в базе данных, что вызывало краш при поиске пользователя.

**Реальная причина:** Пользователи вводили **коды покупки** (6-8 цифр) вместо номеров телефонов при регистрации.

---

## ✅ Что было исправлено

### 1. **Валидация формата номера телефона** 🛡️

**Файл:** `src/main/java/com/plstk/loyaltybot/bot/LoyaltyBot.java`

**Добавлен метод `isValidPhoneNumber()`:**
- ✅ Минимум 10 цифр (отсекает 6-8 значные коды)
- ✅ Максимум 15 цифр (международный стандарт E.164)
- ✅ Специальная проверка для российских номеров (строго 11 цифр)
- ✅ Понятное сообщение об ошибке для пользователей

**Результат:**
```
Пользователь вводит: "8300088" (код покупки)
Бот: ❌ Некорректный формат номера телефона!
     ⚠️ Не вводите код покупки вместо номера телефона!
```

### Шаг 1: Backup базы данных (ОБЯЗАТЕЛЬНО!)

```bash
cp data/loyaltydb.mv.db data/loyaltydb.mv.db.backup-$(date +%Y%m%d)
```

### Шаг 2: Очистить невалидные номера

```sql
-- Рекомендуется: мягкое удаление
UPDATE users
SET 
    phone_number = '',
    state = 'NEW'
WHERE 
    phone_number IS NOT NULL 
    AND phone_number != ''
    AND LENGTH(REGEXP_REPLACE(phone_number, '[^0-9]', '')) < 10;
```

См. `scripts/cleanup-invalid-phones.sql` для других вариантов.

### Шаг 3: Исправить администраторов
