## 🗂 Описание модулей

### 📱 Bot (Telegram Bot)
- `LoyaltyBot.java` - основной класс бота, обрабатывает все входящие сообщения и команды

### 🔧 Config (Конфигурация)
- `BotConfig.java` - настройки подключения к Telegram API
- `LoyaltyConfig.java` - настройки программы лояльности (пороги уровней, длина кодов и т.д.)

### 🗃 Entity (Сущности БД)
- `User.java` - пользователи системы (клиенты и администраторы)
- `PurchaseCode.java` - коды для подтверждения покупок
- `DiscountCode.java` - промокоды со скидками
- `Transaction.java` - история всех операций с баллами

### 💾 Repository (Репозитории)
- Spring Data JPA репозитории для работы с базой данных

### ⚙️ Service (Бизнес-логика)
- `UserService.java` - управление пользователями, начисление/списание баллов
- `PurchaseCodeService.java` - генерация и валидация кодов покупок
- `DiscountCodeService.java` - управление промокодами
- `TransactionService.java` - создание и просмотр истории транзакций

## 🔄 Основные потоки работы

### Регистрация пользователя
```
User → /start → Bot запрашивает телефон → User отправляет телефон → 
Bot создает User в БД → User получает главное меню
```

### Покупка
```
User нажимает "Я совершаю покупку" → Bot генерирует PurchaseCode → 
User показывает код администратору → Admin вводит код в бота → 
Bot начисляет баллы User и создает Transaction
```

### Просмотр баллов
```
User нажимает "Мои баллы" → Bot показывает баланс и уровень лояльности
```

### Промокоды
```
Admin создает промокоды для всех → Bot рассылает DiscountCode всем users → 
User видит код в разделе "Мои скидки" → User использует код в магазине
```

## 🛢 База данных

### Таблицы:
- `USERS` - пользователи
- `PURCHASE_CODES` - коды покупок
- `DISCOUNT_CODES` - промокоды
- `TRANSACTIONS` - история операций

### Связи:
- User ↔ PurchaseCode (один ко многим)
- User ↔ DiscountCode (один ко многим)
- User ↔ Transaction (один ко многим)
- PurchaseCode ↔ Transaction (один к одному)

## 🔐 Безопасность

- Уникальные коды генерируются криптографически безопасным генератором
- Коды имеют срок действия (10 минут по умолчанию)
- Использованные коды нельзя применить повторно
- Разделение ролей пользователь/администратор
